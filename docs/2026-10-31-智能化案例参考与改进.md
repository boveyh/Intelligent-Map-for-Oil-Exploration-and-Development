# 智能化案例参考与改进建议

核查日期：2026-10-31。结合当前项目源码、任务要求与下列第一方网页形成。网页功能依据公开说明核对，未逐一运行外部项目。以下“建议借鉴”是本项目的设计判断，不是对方项目提供的实现。

## 1. 定位与主要缺口

定位为**石油智能决策案例工作台**：观众操作一份具体作业数据，看到方法依据、传统对照、解释分歧和复核线索。

当前已有可计算算法与九张独立场景图，主要缺口是：

1. 输入、训练/标定材料和当前测试对象没有足够清楚地区分。
2. 观众能看见分数，但不容易追问某个结论由哪些样本、特征或参数形成。
3. 分类输出到下一步作业之间还缺明确的复核对象与约束；不能把分类准确率直接换算为增产收益。
4. 主要证据仍是合成数据；真实数据不能继续排在装饰和数量扩张之后。
5. Hough 与标准化有价值，但不能凭名称把它们算成已训练的机器学习模型。

推荐每例按同一条证据链展开：**当前判断任务 → 已知样本/观测 → 方法实际运算 → 与传统方法的分歧 → 在同一测试集上的验证 → 需要谁复核什么。**

## 2. 已核查的参考项目

### A. Fit Lab：最贴近当前测井案例

- [项目首页](https://www.andymcdonald.scot/labs/fit-lab/)；[工作台](https://www.andymcdonald.scot/labs/fit-lab/workbench/)；[KNN 案例](https://www.andymcdonald.scot/labs/fit-lab/k-nearest-neighbours/)。
- 已核对：围绕井曲线比较方法，提供输入、数据条件和验证方式的组合；KNN 页展示近邻投票，区分合成井与真实井。
- 建议借鉴：把观众的注意力固定在同一个测试井段；先定位分歧点，再查看实际参与判断的样本。用于 w4、w2、缺失补全。
- 本项目保持作业案例导向，入口按“解释任务/井段/复核事项”组织，不改造成算法课程目录。
- [作者权利说明](https://www.andymcdonald.scot/labs/fit-lab/creator/)明确限制代码、图、文字及合成井的复制和再使用。本轮只参考公开交互思路，使用自己的算法、数据生成器和图像。

### B. FORCE 2020：学习石油任务的评估设计

- [组织方仓库](https://github.com/bolgebrygg/Force-2020-Machine-Learning-competition)。
- 已核对：岩性预测任务使用井曲线及相关地质信息；评价引入误判代价矩阵，并组织隐藏数据评分。
- 建议借鉴：w4 保留整井盲测；区分各岩性召回率和具体误判，不让一项总分代替地质解释。若增加代价矩阵，须声明来源，不能自行给高风险错误随意赋值。
- 真实数据作为下一阶段候选。正式接入前确认所选文件、标签和分发条件；本轮未下载、训练或把竞赛得分当成本项目效果。

### C. SLB / Equinor 自主钻井：学习结果如何进入作业闭环

- [2024-01-30 的官方案例](https://investorcenter.slb.com/news-releases/news-release-details/slb-and-equinor-drill-most-autonomous-well-section-date)。
- 已核对：案例将自动化作业、AI 钻进控制、轨迹控制及井计划连接起来。这是企业公开披露，不是独立复现实验。
- 建议借鉴：每个案例在模型输出后增加“作业人员下一步看什么、哪些约束必须满足”。例如 pr1 给巡检复核线索，c1 指出需进一步测量的井段。
- 不直接复刻工业控制系统，不把该案例中的现场效果归因到本项目简单模型，也不为本项目填写无依据的增产/节时数字。

### D. TensorFlow Playground：学习可控条件下的模型比较

- [官方演示](https://playground.tensorflow.org/)。
- 已核对：可调整输入特征、噪声和训练/测试比例，观察预测面及训练/测试损失。
- 建议借鉴：w4 逐项控制漂移、特征和标准化；pr1 控制噪声及特征消融。一次只改变一个因素，保留同一份测试数据。
- 参考它的交互实验方法；本项目仍展示具体井段任务，不增加泛化的神经网络教学章节。KNN 也不播放虚构的梯度训练过程。

### E. CNN Explainer：学习从总览进入实际中间计算

- [演示](https://poloclub.github.io/cnn-explainer/)；[项目代码与论文说明](https://github.com/poloclub/cnn-explainer)。
- 已核对：项目将网络总览与局部运算联系起来，浏览器计算；仓库标注 MIT 许可证。
- 建议借鉴：让“选中数据 → 关键证据 → 预测结果”联动。当前 KNN 显示真实近邻；只有以后确实加入 CNN，才展示该网络算出的特征图、卷积或掩膜。
- 本轮不引入它的网络或源码；不生成一张虚构激活热图来冒充本项目解释结果。

### F. What-If Tool：学习单点差异与复核

- [官方反事实示例说明](https://pair-code.github.io/what-if-tool/learn/tutorials/counterfactual/)。
- 已核对：可为选定样本寻找预测不同的相近样本，并比较输入与输出。
- 建议借鉴：选中某深度点时对照两种方法，定位最容易导致判断变化的观测差异。若以后加入数值扰动，明确它是模型敏感性实验，不是地质因果结论或实际作业干预。
- 本轮实现的是近邻证据和方法分歧定位，没有声称实现最小反事实求解。

### G. SEG 2016 ML Contest：参考盲井验收，不直接打包数据

- [组织方仓库与说明](https://github.com/seg/2016-ml-contest)。
- 已核对：使用未公开相标签的井进行评分，要求代码可运行，并处理模型的随机波动。
- 建议借鉴：训练井与测试井独立，报告跨种子的稳定性；禁止挑选正确样本作为全部展示数据。
- 仓库 README 的 Licenses 段对数据另有使用限制，不能仅凭仓库的许可证标记就认为全部数据可再分发。此项先作为评估方式参考。

### H. ONNX Runtime Web：以后确需神经网络时的部署备选

- [官方 Web 指南](https://onnxruntime.ai/docs/tutorials/web/)。
- 已核对：支持使用 JavaScript 在浏览器部署模型。
- 对本项目的判断：现有 KNN/回归直接用 JS 实现，暂不增加运行库。若引入离线训练的轻量网络，先验证运行时加权重后的包体积、算子支持、接收站点宿主和双击离线能力；不能直接假设满足 6 MB 与 file:// 要求。

## 3. 计划应怎样重排

| 顺序 | 要完成的内容 | 验收依据 |
|---|---|---|
| 1 | 明确每例的学习/标定/经典算法/质量控制性质 | 实际实现、模型输入、已知标签、输出对象均可指出 |
| 2 | 主例 w4 显示逐点判断证据 | 选择深度点 → 高亮样本 → 实际近邻与投票 → 当前输出；与推理共用同一计算 |
| 3 | 修正评价边界 | c1 剔除标定段评价；各例按未见井/未见种子验证；不以训练指标报效果 |
| 4 | 接入一例许可明确的真实数据 | 完整保留测试划分、预处理、来源和类别定义；重新计算结果，不能沿用合成分数 |
| 5 | 增加可解释的消融/敏感性实验 | 同数据比较缺少关键特征、未标准化、高噪声等条件下的真实结果 |
| 6 | 补作业复核闭环与发布验收 | 复核名单不偷看真值；包可跨原框架导入、无后端、离线约束通过 |

真实数据接入时，公开数据的岩性体系不一定等于当前五类，必须声明类别映射或保留原类；展示窗口与完整测试集指标分开，不筛掉模型失败的深度点。
